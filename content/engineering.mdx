## Start with the decision

Before choosing sensors or drawing a dashboard, write down the decision someone needs to make. A workshop supervisor might need to know whether a process has stopped, while a project lead needs to see which tasks are waiting for review. These are different questions and may need different data.

For each proposed measure, identify its source, unit, owner and expected update interval. Ask what action changes when the value changes. If nobody can describe that action, keep the measure out of the first release.

## Separate visibility from alerts

A dashboard can show information that is useful occasionally. An alert interrupts someone and needs a stronger reason to exist. Agree the condition, the person responsible, the expected response and what happens if they cannot respond.

Consider duration as well as a threshold. A brief fluctuation may need different treatment from a sustained change. Test proposed rules against representative operating conditions before turning notifications on. Record an acknowledgement and a resolution separately so a dismissed notification does not imply that the underlying issue is fixed.

## Show when the data is uncertain

A stale reading should not look like a live one. Display timestamps, connection status and missing values clearly. Keep units visible and distinguish an unavailable source from a valid zero.

Decide how the system behaves when a sensor disconnects or readings arrive late. Where a signal might lead to a control action, agree limits and manual override with the responsible operational team. A monitoring dashboard is not a substitute for the safeguards required by the equipment.

## Ignore noise deliberately

Avoid treating every available measurement as equally useful. Duplicate notifications, unowned alerts and charts with no decision attached make a system harder to use.

Begin with a focused view and review it with the people on shift. Ask which alerts led to action, which arrived too late and which were ignored. Adjust the rules and document why. The aim is a system whose signals have a clear purpose, not a screen filled with numbers.
